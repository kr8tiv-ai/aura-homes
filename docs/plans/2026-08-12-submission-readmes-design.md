# Aura Homes submission READMEs — design record

## Reader and outcome

The primary reader is an OKX BuildX judge or open-source reviewer arriving with no prior context. Within 60 seconds they should be able to understand Aura's customer, open the live project journey, distinguish working proof from pilot data and future plans, and find the X Layer evidence.

The secondary reader is a design/technology visitor arriving through `kr8tiv-io/aurahomes-site`. They should see the visual story and reach the canonical submission without encountering a second, conflicting source of technical truth.

## Chosen approach

Use `kr8tiv-ai/aura-homes` as the expansive canonical submission. Use `kr8tiv-io/aurahomes-site` as a shorter portfolio synopsis linking back to the canonical repository.

The canonical narrative order is:

1. Branded hero and one-sentence product promise.
2. A 60-second judge path with direct actions.
3. Three approachable user journeys: design/build, build on owned land, choose a finished home.
4. A capability matrix labelled Live, Pilot, Testnet, In build, or Planned.
5. The persistent project model and editor/export story.
6. Land, contractor, quote, and manufacturer evidence boundaries.
7. X Layer/OKX architecture and reproducible testnet proof.
8. HOMES trust concept and public zero-state ledger.
9. The later owner-led RWA launchpad with separate token-lock, project-vault, and market-liquidity ledgers.
10. Safeguards, verification evidence, setup, roadmap, docs, and credits.

## Visual system

- Reuse the authored Nordic house/social artwork already shipped with the application.
- Reuse the existing Aura pipeline, cost-band, escrow, logo, and section-rule assets.
- Keep the paper/ink/emerald system and restrained voice.
- Prefer diagrams, compact tables, status badges, and short declarative headings over decorative emoji walls.

## Claim boundary

- `Live` means the deployed website or browser feature works now.
- `Pilot` means the engine works over explicitly limited or demonstration/public inputs.
- `Testnet` means code and deployed X Layer testnet state; no mainnet or real customer funds.
- `In build` means code exists but the end-to-end customer outcome is incomplete.
- `Planned` means narrative/design only, including HOMES, the trust, staking, project pools, and the RWA launchpad.
- The current X Layer configuration and fresh RPC read-back outrank stale prose.
- Aura prepares and explains. Users confirm payments and real-world decisions. Licensed people complete regulated professional work.

## Reader test

A cold reader must be able to answer these questions without searching the repository:

1. What can a normal non-crypto person do with Aura?
2. What can a judge try in under one minute?
3. What is genuinely deployed on X Layer testnet?
4. What is HOMES, and what does not exist yet?
5. How would a future owner-led unique-stay project separate token support, construction funding, and market liquidity?
6. Where are the tests, source documents, and live demo?
